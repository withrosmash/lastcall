# Design sources, in order of precedence

1. **`HANDOFF.md`** and **`../css/tokens/*.css`** — the current source of truth, from the Claude Design system package. Token files are copied in verbatim so a future design update is a file swap, not a merge.
2. **`screenshots/`** — the 13 screens and 3 share-card layouts as rendered by the design prototype. Use these to check the build against intent.
3. **`round2/`** — Claude Design's round 2 handoff (bloom, light mode, avatar art and items, moments, share card, extras). Start at `round2/README.md`; decisions in `round2/NOTES.md`. `round2/designs/avatar-draw.js` is the art source of truth; use `round2/designs/share-card.js` (the newer copy, with the light card).
4. **`BRIEF-ROUND-2.md`** — the second brief (September 2026): stronger forest bloom, light mode with a cobalt bloom, the avatar art pass and unlockable items. Overrides the original brief's "no light mode" rule.
5. **`AVATAR-MOTION.md`** — the avatar's grid, expressions, movements and rules.
6. **`BRIEF.md`** and **`handoff.html`** — the original brief and first-pass handoff written before the design system existed. Kept as history. Superseded; do not build from these.

## Where the build knowingly differs

- **Fake Android chrome is not implemented.** The prototype draws a status bar (1:42, signal, wifi, battery) and a gesture pill. Those are drawn by the OS on a real device; the build uses safe-area insets instead.
- **Icons are inlined, not loaded from the Lucide CDN.** The app boots offline from a service worker, so a remote icon fetch would be the one thing on screen that fails. Same glyphs, same 24px grid and 1.5px stroke — see `js/icons.js`.
- **No `backdrop-filter` on the bottom sheet.** The panel fill `#0D0D0D` is opaque, so `--blur-sheet` has nothing to act on, and it forced a compositing layer that let the screen beneath bleed through. Consistent with the system's own rule: blur only where something is genuinely behind it.
- **Map tiles are Esri Dark Gray Canvas, not offline tiles.** The brief asks for bundled offline tiles and no cross-origin imagery; that needs packaged map data and is still open. Standard OSM raster was tried first and rejected — it is light, fights the true-black ground, and left the stats strip unreadable. CARTO `dark_all` was used until September 2026, when it began stamping "API KEY REQUIRED" over keyless tiles. Esri's canvas is keyless and CORS-enabled (so the share card can draw it), but greyer than CARTO and has no data past zoom 16. Share cards with a map carry a small Esri/OpenStreetMap credit in the top corner.
- **There is a settings screen.** The system fixes the hydration threshold at 5 with no way to change it; the client asked for it to be configurable, so `Settings → Reminders` offers 3/4/5/6/8 or Never, built from the existing Chip component and reached from History.
- **The amber WarningBanner has a second use.** The system reserves amber for hydration alone. It is also used when Android's battery optimisation is on, because Samsung's Device Care will stop the foreground service and silently end a night mid-record — a consequence at least as serious as being behind on water, and exactly the shape the component exists for. It still only appears when something is genuinely wrong, never at rest.
- **Light-mode badges are generated, not drawn.** `scripts/light-badges.mjs` swaps each badge's template colours for the light tokens (white disc with a `#D5DDE9` hairline, deep accents, navy highlight) into `icons/badges/light/`. Rerun it when a badge is added. The share card isn't themed, so it always uses the dark art.
- **Maps in light** use Esri's World Light Gray Canvas, with the route in `#3FC79E` over a `#0B6E55` under-stroke, as specified. A few map and chrome colours that were hard-coded for black now come from app-level variables in `style.css` (`--chrome-bg`, `--attrib-bg`, `--me-halo`, `--stop-halo`, `--map-ground`).
- **The round 2 avatar engine is ported, not replaced.** `js/avatar.js` keeps Claude Design's shapes, slots, tones, layer order and items verbatim, and draws each part into a movable group (root, body, head, hair, feet) so the animations still work. Arms by the sides use the designed pixels; raised arms use the designed arms-up path; holding, sipping, waving and swinging are drawn from angles in the same outline style. The reaction props (pint, water glass, burger, pin) were resized for the bigger round 2 head. The check-in pin drops beside the head, because the art reaches the top of the grid.
- **The six round 2 badges were rebuilt on the shipped template.** The delivered SVGs used a thinner ring, smaller symbol and different glow, and carried about 15KB of metadata each; their symbols were kept and set on the same template as the other 32, as their README asked. The `-locked` files aren't used: the app greys locked badges itself.
- **Customise autosaves.** At the client's request every change saves as it's made; the design's Save look / Cancel became Done and Undo changes (back to the look you opened the screen with). The whole screen scrolls rather than just the panel.
- **The share card keeps three things the design dropped**, at the client's request: the Badges and Stops elements (on the route card they stack above the stats and the map gives up the room), and the Light / Halo / Dark text themes on photo cards. The route card's Dark / Light chips are the design's. On the light route card the badges use the generated light discs.
- **The history slider reads the place, not the drink count**, as designed: the stop's name within 2.5% of a check-in, otherwise "Between stops".
- **Icons are drawn from the avatar engine.** `scripts/icons.mjs` renders direction A (the default face, happy, on the forest bloom) for the launcher (legacy, round, and adaptive foreground and background layers), a themed-icon monochrome layer, the web icons, a 1024px store icon (`design/round2/icon-1024.png`) and the splash images, plus the 12 x 12 notification face as a vector. The head crop is one row shorter than the design's, which caught the top of the shoulders. The static splash has no wordmark (it's a bitmap and there's no font renderer in the script); the app's hand-off frame shows it.
- **The light-theme system splash isn't possible**: Android draws the splash before any app code can read the theme, so it's always black. The hand-off frame that follows it does follow the theme (cobalt disc in light).
- **First launch uses the settings route for location**, as the field-tested priming screen did, rather than the plugin's own prompt. It only shows on a genuinely new install: anyone with a night recorded skips it.
- **The app is called Leit, but its insides still say lastcall.** The app ID (`com.withrosmash.lastcall`), the storage key, the native plugin, the notification channels and the CI artifact name keep the old name on purpose: changing them would make Android treat it as a new app and testers would lose their nights. Only what people can see changed. The wordmark is plain "Leit" in the app's typeface until round 3 draws one.
- **The word for an outing is set in one place.** `js/words.js` holds five sets (adventure, outing, quest, sidequest, night) and every user-facing "night" goes through `t()`. The build uses "adventure"; change `WORDING` to try another. Badge names such as "First Night" are unchanged until the modes work (M2).
